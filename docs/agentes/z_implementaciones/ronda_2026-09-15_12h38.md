## Entrega 1 — `keylog --follow --timestamps` (Go + Python)

- **Motivación:** en un lab de red team, las capturas del keylogger sin
  referencia temporal no se pueden correlacionar con sesiones, logs ni
  eventos. El stream imprimía el diff de keystrokes tal cual.
- **Diseño:** función pura en cada cliente — `formatKeylogEvent`
  (`cmd/vault_kernel/main.go`) y `format_keylog_event`
  (`client/vault_kernel_cli.py`) — que recibe el contenido nuevo del
  sondeo, el timestamp y si el buffer envolvió: con timestamps, TODOS
  los eventos se emiten en línea nueva con `[HH:MM:SS]` delante; sin
  timestamps, el comportamiento histórico queda intacto (el sufijo
  continúa la línea; el wrap empieza una nueva). La marca es la hora
  del SONDEO que mostró el contenido — cota honesta, no de la
  pulsación (el buffer del módulo no lleva tiempo por tecla); así está
  documentado en la ayuda, el README, ADR 18 y los docstrings. En
  Python, `keylog_read()` acepta `timestamps=`; en Go, `keylogFollow()`
  firma `(f, intervalMs, timestamps)`. `--timestamps` sin `--follow`
  es error de uso en AMBOS clientes (`parser.error` en Python /
  error de `parseKeylogArgs` en Go).
- **Tests:** `TestFormatKeylogEvent` en ambos lados (4 casos espejo:
  continuación sin ts, wrap sin ts, ambos con ts, contenido con
  espacios nunca mangleado).
- **Cómo probarla:** `go test ./... -count=1` y
  `python3 tests/python/test_cli_parsing.py -v`; en la VM:
  `sudo ./vault_kernel keylog --follow --timestamps` y
  `sudo python3 client/vault_kernel_cli.py keylog --follow
  --timestamps` — Ctrl-C para salir; `keylog --timestamps` (sin
  follow) debe fallar con error de uso en ambos.

## Entrega 2 — Comando `version` en el CLI Python

- **Motivación:** hueco de paridad detectado en la auditoría: el CLI Go
  tiene `version`/`-v`/`--version` desde v3.6; el Python respondía
  "invalid choice". El README dice "legacy, paridad con Go" — ahora es
  cierto también aquí.
- **Implementación:** `format_version_line()` a nivel de módulo replica
  el texto exacto de `printVersion()` de Go — `vault_kernel CLI v3.8
  (ioctl magic 0xC0, signal trigger 35)` — con las constantes reales
  del módulo (`MAGIC`, `MAGIC_SIGNAL`, `CLIENT_VERSION`), de modo que
  cualquier cambio futuro de ABI se refleja solo. Registrado en el
  subparsers y en el dispatcher; el docstring del CLI lo lista.
- **Tests:** `TestVersionCommand` (2 tests: el texto exacto de
  `format_version_line`, y e2e de `main()` con argv simulado — el
  comando no toca el dispositivo).
- **Cómo probarla:** `python3 client/vault_kernel_cli.py version` →
  `vault_kernel CLI v3.8 (ioctl magic 0xC0, signal trigger 35)` —
  comparar con `./vault_kernel version` del binario Go: idéntico.
