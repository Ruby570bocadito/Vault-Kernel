## Entrega 1 — `capture` con `hostname` + `kernel_release` (Go + Python)

- **Motivación:** el bundle congelaba EL MÓDULO, no EL MOMENTO. La
  primera pregunta de cualquier revisor de un bundle de evidencia es
  "¿de qué máquina y de qué kernel?" — hoy hay que cruzar el bundle
  con otros logs para responderla.
- **Diseño:** dos campos nuevos en el envelope, en posición
  contractual `client_version` → `hostname` → `kernel_release` →
  `module_in_sysfs`. ADITIVOS: el schema se queda en 1 (la política
  del campo `schema` lo permite explícitamente — "additive fields
  keep it at 1"). Fuentes: Go `os.Hostname()` + nueva
  `runningKernelRelease()` que lee `/proc/sys/kernel/osrelease`
  (procfs, sin structs de `syscall.Utsname`, Linux-only como el
  proyecto); Python `platform.node()` + `platform.release()`. Ambos
  caen a `""` si la fuente falta — una etiqueta ausente no puede
  fallar la captura.
- **Go:** `captureReport` gana los dos campos con tag json en orden;
  `buildCaptureReport` firma ampliada (pura — los tests la ejercitan
  sin dispositivo); `runCapture` colecta y pasa. `TestBuildCaptureReport`
  actualizado (valores nuevos + la aserción de ORDEN contractual
  gana `"hostname"`/`"kernel_release"`); `TestRunningKernelRelease`
  nuevo (no-vacío en Linux, sin whitespace).
- **Python:** `build_capture_bundle` gana los parámetros keyword
  (`hostname=""`, `kernel_release=""`) y las claves en la MISMA
  posición; `capture()` pasa `platform.node()`/`platform.release()`.
  `TestBuildCaptureBundle.test_bundle_shape` actualizado (orden
  completo) + `test_host_context_roundtrip` nuevo (valores y posición
  relativa de claves).
- **Contrato:** `docs/schemas/capture.md` actualizado (ROL 3) —
  ejemplo JSON, tabla de campos y nota de aditividad.
- **Cómo probarlo:** en VM: `sudo ./vault_kernel capture --stdout |
  jq '.hostname, .kernel_release'` → host y release reales; sin
  módulo, la gramática y el builder se verifican por
  `go test -run TestBuildCaptureReport -v` y el unittest espejo.

## Entrega 2 — `watch --count N` (Go + Python)

- **Motivación:** `watch --once` congela UN fotograma y Ctrl-C corta
  el stream a mano — un reporte de deriva (5 paneles a 500 ms) exigía
  un humano con el dedo en la tecla. La simetría natural con
  `keylog --follow --stop-after` (v3.11) estaba a un flag de
  distancia.
- **Diseño:** `--count N` (N >= 1, como mucho una vez) hace que el
  bucle vivo termine tras el fotograma N con la MISMA despedida que
  Ctrl-C/SIGTERM (`[*] watch stopped`) — un solo camino de salida
  limpia, el mismo patrón de `--stop-after`. MUTUAMENTE EXCLUYENTE
  con `--once` (un fotograma no es una ventana — error de uso, clase
  2). Sin `--count` el comportamiento es byte-idéntico al de v3.11.
- **Go:** `watchOpts.count` (0 = ilimitado); `parseWatchArgs` valida
  operando ausente/duplicado/`< 1`/no numérico con `usagef` (el token
  en el mensaje) y la exclusión `--once`+`--count`; el bucle de
  `runWatch` cuenta frames (`for frame := 1; ; frame++`) y retorna
  nil tras el N con la despedida; el restore del cursor sigue en el
  defer (sale limpio también por la vía nueva).
- **Python:** tipo argparse `_count_arg` (int >= 1, errores
  `ArgumentTypeError` espejo del parser Go); guard
  `once and count is not None` DENTRO de `watch()` (stderr +
  `SystemExit(2)`, mismo criterio que el guard de `--stop-after` —
  testeable sin subproceso); el bucle cuenta `frames` y termina con
  `print("[*] watch stopped")`.
- **Tests:** Go — `TestParseWatchArgsCount` (2 válidas combinadas con
  `--interval` en ambos órdenes, defaults intactos, 6 casos de
  rechazo todos como `usageError`). Python — `TestWatchCount` (tipo
  argparse con 0/-3/abc rechazados, guard de exclusión con código 2
  y mensaje en stderr, y **test de bucle real** con ioctl simulado:
  3 payloads de GET_STATS/LIST_HIDDEN, `count=3` → exactamente 3
  paneles + despedida, verificado con `text.count("vault_kernel
  watch") == 3`). El wiring de dispatch se fija extendiendo los dos
  tests de `TestWatchOnceWiring` (fake_watch acepta y captura
  `count`; default None en ambos casos).
- **Wiring:** usage Go (línea `watch` + bloque de exit codes —
  `printUsageTo`), epílogo Python (línea watch + help + exit codes),
  completions bash y zsh (`watch → --interval --once --count`), test
  de paridad actualizado (10 flags, 23 comandos).
- **Cómo probarlo:** en VM: `sudo ./vault_kernel watch --count 5
  --interval 200` — tras el quinto panel el CLI termina solo con
  `[*] watch stopped` y el cursor restaurado; sin módulo, la
  gramática se verifica por `go test -run TestParseWatchArgsCount -v`
  y el unittest del bucle.

  quedaron como funciones puras compartidas por el dispatcher
