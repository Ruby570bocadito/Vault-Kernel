## Entrega 1 — Parser compartido de reportes (Go + Python, con tests)

- **Motivación:** el reporte de `GET_STATS` emite VARIOS pares
  `clave=valor` por línea (`module=vault_kernel version=3.5`) y los
  cuatro puntos de parseo existentes (2 Go, 2 Python) partían cada
  línea por el primer `=` — el bug que ROL 4 corrige. En vez de
  parchear 4 copias, la decisión (con el Director) es UN parser como
  fuente de verdad por cliente, con tests que fijan el formato del
  kernel en CI.
- **Implementación Go:** `client/go/internal/vaultkernel/report.go` —
  `ParseStatsReport(report) map[string]string` (split por espacios,
  luego cada token en su primer `=`; tokens sin clave ignorados) y
  `ParseHiddenList(report) HiddenList` (secciones `--- Hidden PIDs /
  Files / Ports ---`; el contexto de sección decide la interpretación,
  así que un fichero llamado `pid: 5` sigue siendo un nombre de
  fichero; números no parseables se descartan; slices no-nil para que
  el JSON renderice `[]` y no `null`).
- **Implementación Python:** `parse_stats_report()` y
  `parse_hidden_list()` a nivel de módulo en
  `client/vault_kernel_cli.py`, espejo exacto del Go (mismas
  semánticas de arista: `=huerfano` ignorado, primer `=` sólo,
  `a=b=c` → valor `b=c`).
- **Tests:** `client/go/internal/vaultkernel/report_test.go` (8 tests:
  fixture EXACTO del snprintf de `src/ioctl.c`, pares múltiples por
  línea, aristas, secciones vacías → `{"pids":[],"files":[],"ports":[]}`
  en JSON, basura numérica) y
  `tests/python/test_cli_parsing.py` (16 tests unittest: mismos
  fixtures + end-to-end de `stats --json` y `doctor --json` con ioctl
  stubbed + unidades de `--interval`).
- **Cómo probarlo:** `go test ./... -count=1` en `client/go/` y
  `python3 tests/python/test_cli_parsing.py -v` — ambos corren en la
  CI de cada push.

## Entrega 2 — `list --json` y `doctor --json` (Go + Python)

- **Motivación:** completar la superficie JSON de scripting del
  backlog de la ronda 2: `stats --json` existía, pero el listado y el
  diagnóstico seguían siendo solo texto.
- **`list --json`:** emite
  `{"pids": [...], "files": [...], "ports": [...]}` con `MarshalIndent`
  (Go) / `json.dumps(indent=2)` (Python) sobre `ParseHiddenList`.
  Flags nuevos en ambos CLIs (`vault_kernel list --json`,
  `python3 vault_kernel_cli.py list --json`).
- **`doctor --json`:** `runDoctor` reestructurado alrededor de un
  `doctorReport` (Go) / dict (Python) con el MISMO flujo de comprobaciones;
  en modo texto la salida es idéntica a v3.5 (salvo los valores, que
  ahora el parser compartido extrae bien); en modo JSON emite UN
  documento estable: `client_version`, `device_present`, `device_open`,
  `stats_responds`, `module_version`, `version_match`, `uptime_s`,
  `hooks_installed`, `hooks_planned`, `module_in_sysfs`,
  `keylog_responds`, `list_responds`, `warnings`. Los fallos de
  dispositivo también emiten JSON (con las comprobaciones ya
  ejecutadas) y conservan el exit no cero — scripts de lab pueden
  hacer `doctor --json | jq` tanto en éxito como en fallo.
- **Smoke tests sin módulo (este entorno):** `doctor --json` de ambos
  CLIs → JSON válido + exit 1:
  `{"client_version": "3.6", "device_present": false, "warnings": 0}`.
- **Esquema testado:** los tests end-to-end de doctor fijan el esquema
  completo (éxito, mismatch de versión con `warnings: 1`, y fallo de
  dispositivo) para que cualquier cambio futuro de formato rompa la CI
  y no un script de lab.
