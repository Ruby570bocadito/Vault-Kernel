## Corrección 1 (MEDIA, control plane) — el contrato de exit codes 0/1/2

- **Descripción reproducida (commit base, tabla completa en el
  informe del Director):** Go `hide-file` sin operando → exit 1 con
  "cannot open /dev/vault_kernel" (el error de DISPOSITIVO
  enmascaraba el de uso porque `run()` abría el device ANTES del
  switch que parsea); argparse → exit 2. Python `keylog
  --timestamps` sin `--follow` → 2 (parser.error) pero `keylog
  --stop-after 5` sin `--follow` → 1 (SystemExit-string). Invocación
  desnuda: Go 0 / Python 1.
- **Clase de bug:** `$?` es la ÚNICA forma de clasificar un fallo
  sin parsear texto; dos gramáticas de salida para el mismo comando
  rompen todo script multi-cliente (la misma lección de las rondas
  6-8: la superficie invisible es interfaz).
- **Solución — contrato de TRES clases idéntico en ambos clientes
  (ADR 22):** `0` éxito · `1` runtime (dispositivo/ioctl/informe
  vacío/fichero no escribible) · `2` uso (gramática, valores,
  precondiciones, comando desconocido, invocación desnuda).
  - **Go:** tipo `usageError` + `usagef()`; TODOS los parsers de
    gramática (`strictArgs`, `posixOperandArgs`, `parseFlagOnly`,
    `parseGiveRootPID`, `parsePIDArg`, `parsePortArg`,
    `parseShellTarget`, `parseKeylogArgs`, `parseCaptureArgs`,
    `parseWatchArgs`, `parseMagicEncodeArgs`) y los validadores de
    valor nuevos (`validateFileName`, `validateMagicWord`, el check
    255 B de shell SUBIENDO a la gramática) devuelven la clase uso;
    `main()` la mapea con `errors.As` → exit 2, resto → 1.
  - **Go — gramática ANTES de dispositivo:** `run()` reestructurado —
    cada case parsea con los parsers puros y devuelve la closure de
    ejecución; `openDevice()` corre UNA vez tras el switch. CIERRA la
    deuda de la ronda 4: con módulo cargado el comportamiento es
    idéntico; sin él, el error de uso honesto (2) sustituye al de
    dispositivo (1) que lo ocultaba.
  - **Python:** `_reject` → stderr + `SystemExit(2)`; guard de
    `--stop-after` → stderr + 2 (alineado con `--timestamps`);
    invocación desnuda → `parser.print_help(file=sys.stderr)` + 2.
- **Tests:** Go — `TestGrammarErrorsAreUsage` (18 casos: cada parser
  con su error de gramática DEBE ser `usageError`; los operandos
  válidos pasan; un error plano NUNCA matchea) y `TestParseWatchArgsCount`
  (6 rechazos como usageError). Python — `TestExitCodeContract` con
  **SUBPROCESOS REALES**: 9 celdas de la clase 2 (incluida la
  invocación desnuda y `--count`+`--once`), la clase 1 (dispositivo
  ausente) y la clase 0 (`version`/`help`/`status --json` con parseo
  del documento) — la única forma de fijar lo que `$?` ve.
- **Cómo verificarlo:** `./vault_kernel hide-file a b ; echo $?` → 2
  (y el mensaje ya no menciona el dispositivo); `python3
  vault_kernel_cli.py keylog --stop-after 5 ; echo $?` → 2;
  `python3 tests/python/test_cli_parsing.py TestExitCodeContract -v`.

## Corrección 2 (MEDIA, camino de error) — un ioctl fallido en Python salía con exit 0

- **Descripción (leída del código, confirmada con test):**
  `_ioctl` capturaba `OSError`, imprimía `[-] ioctl failed: ...` y
  devolvía False; los comandos hacen `if self._ioctl(...): print
  éxito` y terminan normalmente → exit 0. Con el módulo cargado,
  un `hide-pid` rechazado por EPERM habría "tenido éxito" a ojos del
  shell. El cliente Go en la misma celda sale 1.
- **Solución:** `_ioctl` lanza `SystemExit(1)` tras reportar (clase
  runtime) — los condicionales `if self._ioctl(...)` quedan como
  camino de éxito puro. Paridad de clase con Go por construcción.
- **Test:** `TestIoctlFailureRuntimeClass` — mock de `fcntl.ioctl`
  que lanza `OSError(EPERM)` → `hide_pid(5)` DEBE terminar con
  `SystemExit` código 1.

## Recomendaciones de seguridad generales para el resto de agentes

1. **Cada error nuevo necesita CLASE, no solo mensaje:** si nace en
   la capa de gramática, `usagef` (Go) / stderr + exit 2 (Python);
   si es runtime, error plano / `SystemExit(1)`. El test de
   subproceso es el único árbitro válido de la clase.
2. **La gramática no toca el dispositivo:** los parsers nuevos deben
   ser puros y correr ANTES de `openDevice()` — el dispatcher Go ya
   lo garantiza estructuralmente; no relajarlo.
3. **Los caminos de ERROR son contrato:** el exit-0 de `_ioctl`
   (corrección 2) existió durante 9 versiones porque nadie probó el
   fallo con un mock. Todo camino que imprima `[-]` debe terminar en
   un test que exija su código.
4. **Ediciones por bytes** (política ronda 8, re-validada): anchors
   con conteo esperado, scripts que abortan ante desviación,
   `gofmt -l` en el smoke de cierre.
5. **Nota operacional recurrente:** el token de GitHub del owner
   sigue expuesto en el chat desde la ronda 1 — el repo sigue limpio
