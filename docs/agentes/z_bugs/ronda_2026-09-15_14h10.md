## Corrección 1 (MEDIA-BAJA, control plane) — Go aceptaba valores de flag que empiezan por `-`

- **Descripción:** `parseKeylogArgs` y `parseCaptureArgs` consumían el
  token siguiente a `--output`/`--out` como FILE sin mirar su
  contenido: `keylog --output --follow` fijaba outputPath = `"--follow"`
  (con módulo cargado: fichero llamado `--follow`; sin módulo: el
  error de apertura del dispositivo OCULTABA la brecha de gramática) y
  `capture --out --json` fijaba outPath = `"--json"` (el bundle se
  habría escrito en un fichero con nombre de flag). El CLI Python
  rechaza los tres inputs con `expected one argument` — verificado por
  reproducción en ambos clientes sobre el commit base.
- **Clase de bug:** la misma que la ronda 6 erradicó para operandos
  posicionales (errores de uso silenciosos), pero en la capa de
  VALORES de flag — la matriz comando×cliente del Director se extiende
  con esta dimensión y la ronda cierra la clase entera, no casos.
- **Solución:** regla global en los DOS parsers: un FILE operand que
  empieza por `-` es un operand FALTANTE. El error nombra el token
  ofensivo y enseña el escape documentado: `--out requires a FILE
  operand (got "--json"; paths starting with '-' need a ./ prefix)`.
  Los docstrings de ambos parsers documentan la regla.
- **Nota de paridad honesta:** argparse rechaza la forma espaciada
  `--output -foo` pero acepta la forma `--output=-foo` (artefacto de
  argparse, no contrato); Go no tiene forma con `=`, así que el escape
  canónico en AMBOS clientes es `./-foo` (un path con guion INTERIOR
  como `cap-1.log` sigue siendo válido — test cubre ambos lados).
- **Archivos:** `client/go/cmd/vault_kernel/main.go`
  (`parseKeylogArgs`, `parseCaptureArgs` + docstrings),
  `main_test.go` (`TestFlagValuesRejectLeadingDash`: 7 inputs
  rechazados, el error nombra el token, `cap-1.log` válido,
  `./-foo` válido como escape documentado).
- **Cómo verificarlo:** `go test ./cmd/vault_kernel/ -run
  TestFlagValuesRejectLeadingDash -v`. Smoke con binario real SIN
  módulo llega al error de apertura (arquitectura de la ronda 4:
  gramática post-apertura — decisión respetada; el test unitario es la
  verificación de la regla). En VM: `keylog --output --follow` da el
  error de uso, no crea fichero.

## Corrección 2 (BAJA, paridad del camino de error JSON) — `stats --json` Python con reporte vacío

- **Descripción:** en `VaultKernelClient.stats`, la rama
  `if not output` se evaluaba ANTES que `elif as_json`: con el
  dispositivo devolviendo un reporte vacío, el modo JSON imprimía el
  TEXTO `(no stats returned)` y salía 0 — un consumidor con `jq`
  recibía texto no-JSON con código de éxito. El cliente Go
  (`showStatsJSON`) falla con `module returned an empty stats report`
  y exit 1. Reproducido sobre el commit base en este entorno.
- **Causa raíz:** orden de las ramas del condicional (el camino JSON
  nunca llegó a ejecutarse con buffer vacío; no había test de ese
  camino en modo JSON).
- **Solución:** el modo JSON se comprueba PRIMERO: reporte vacío O
  basura sin pares `k=v` → `SystemExit("[-] module returned an empty
  stats report")` (mismo mensaje y exit 1 que Go). El modo texto
  conserva el placeholder `(no stats returned)` y el print del
  reporte.
- **Archivos:** `client/vault_kernel_cli.py` (`stats()` reordenado +
  comentario del contrato), `tests/python/test_cli_parsing.py`
  (`TestStatsJsonEmptyReport`: 4 tests — JSON vacío falla, JSON
  basura falla, texto vacío conserva placeholder, texto OK imprime).
- **Cómo verificarlo:** `python3 tests/python/test_cli_parsing.py
  TestStatsJsonEmptyReport -v`; en VM con el módulo descargado:
  `vault_kernel_cli.py stats --json` → exit 1 con mensaje (antes:
  texto y exit 0).

## Corrección 3 (BAJA, fiabilidad del plano de captura) — señales y despedida (análisis y plan de este rol; implementación de ROL 2)

- **Descripción:** los cuatro bucles largos solo terminaban limpios
  por Ctrl-C: SIGTERM mataba el proceso a mitad de escritura del sink
  de `--output` (el flush por evento limita la pérdida, la parada
  ordenada es la barrera correcta), el cursor de `watch` podía quedar
  oculto si la terminación era TERM, y Go salía en SILENCIO por
  Ctrl-C mientras Python imprimía `[*] Follow stopped` — paridad rota
  observable.
- **Severidad:** BAJA en seguridad, MEDIA en práctica de lab: el
  flujo documentado de evidencia (`keylog --follow --output …` bajo
  systemd/kleines wrapper) se cortaba de la peor forma posible.
- **Solución (decisión de diseño conjunta con ROL 2):** SIGTERM se
  enruta por el MISMO camino de parada limpia que Ctrl-C en los
  cuatro bucles; en Python mediante un handler que lanza
  KeyboardInterrupt (los finally existentes hacen el trabajo — cero
  lógica duplicada); en Go con `signal.Notify(os.Interrupt,
  syscall.SIGTERM)` y `select` en el sleep (parada inmediata, sin
  esperar el tick). Despedida unificada `\n[*] Follow stopped` en
  ambos clientes; `watch` conserva su mensaje. Detalle de
  implementación y smoke en el informe de ROL 2.
- **Lección de política (para recomendaciones):** la paridad de
  gramática de las rondas 4-6 cubría ARGUMENTOS; los CAMINOS DE
  SEÑAL también son superficie del cliente y se auditan desde esta
  ronda (nueva fila en la matriz del Director).
