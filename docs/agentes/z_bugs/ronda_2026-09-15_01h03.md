## Corrección 1 (MEDIA) — Parser de `GET_STATS`: `stats --json` corrupto y check de versión de `doctor` muerto

- **Descripción:** el módulo emite el reporte con VARIOS pares
  `clave=valor` por línea (`module=vault_kernel version=3.5`,
  `hooks_installed=7 hooks_planned=7`, …). Los parsers de ambos CLIs
  partían cada LÍNEA por el primer `=`: cada par después del primero
  se tragaba dentro del valor del anterior. Reproducido con el código
  real del cliente (arnés con ioctl stubbed,
  `scripts/repro_r3_stats_parse.py`): 6 claves de 10 — perdidas
  `version`, `hooks_planned`, `hidden_pids`, `hidden_ports`; valores
  mezclados como `"hooks_installed": "7 hooks_planned=7"`.
- **Superficie afectada:**
  - `stats --json` (Go y Python) — **regresión introducida en la ronda
    2**: se estrenó v3.5 con este parser y no hubo forma de detectarlo
    sin módulo (lección: la lógica de parseo sin fixture del formato
    real del kernel no está verificada).
  - `doctor` modo texto (Go y Python) — desde v3.4: el aviso
    "[WARN] client vX != module vY" **nunca pudo dispararse**
    (`stats["version"]` quedaba vacío) y la línea de hooks se imprimía
    mangleada (`[ OK ] 7 hooks_planned=7/ syscall hooks installed`).
- **Severidad:** MEDIA (el plano de diagnóstico del lab da datos
  erróneos/ausentes; la herramienta de verificación de ABI no verifica).
- **Causa raíz:** el formato del reporte (pares múltiples por línea,
  legible para humanos) se parseó asumiendo un par por línea.
- **Solución:** parser por tokens compartido (ROL 2):
  dividir por espacios en blanco y después cada token en su primer `=`.
  Los 4 puntos de parseo ahora lo usan: `showStatsJSON` (Go) y
  `stats(as_json=True)` (Python) rewireados por ROL 4; `runDoctor`/
  `run_doctor` reestructurados sobre el parser en la reorganización
  para `doctor --json` (ROL 2). El formato del kernel NO cambia.
- **Archivos:** `client/go/cmd/vault_kernel/main.go` (`showStatsJSON`,
  `runDoctor`), `client/vault_kernel_cli.py` (`stats`, `run_doctor`).
- **Cómo verificarlo:** (1) `go test ./... -count=1` —
  `TestParseStatsReportKernelFixture` fija el formato EXACTO del
  snprintf de `src/ioctl.c`; (2) `python3
  tests/python/test_cli_parsing.py` — 16/16, incluidos end-to-end de
  `stats --json` (las 10 claves, números como números) y `doctor --json`
  (éxito, mismatch de versión → `warnings: 1`, fallo de dispositivo);
  (3) tras el fix, el mismo arnés del repro devuelve las 10 claves
  correctas; (4) en la VM: `stats --json | jq .version` → `"3.6"` y
  `doctor` con un módulo viejo debe mostrar el `[WARN]` (esto último
  requería antes un desajuste real que nunca se mostraba).

## Corrección 2 (MEDIA) — `keylog --interval` de Python dormía segundos (documentado: milisegundos)

- **Descripción:** la ayuda (`--interval MS`, "default 500, min 50"),
  el docstring y el CLI Go (`time.Duration(n) * time.Millisecond`)
  trabajan en MILLISEGUNDOS; el código Python hacía
  `interval = max(args.interval, 0.05)` y `time.sleep(interval)` —
  SEGUNDOS. Con `--interval 500` el poll dormía 500 s (8,3 minutos)
  frente a los 500 ms del Go: 1000x, el `--follow` quedaba inutilizable
  siguiendo la documentación.
- **Severidad:** MEDIA (funcionalidad de la ronda 2 rota en un cliente
  por desajuste de unidades entre clientes hermanos).
- **Causa raíz:** paridad de unidades no testada entre Go y Python;
  el default interno (0.5 s) enmascaraba el bug solo en el caso sin
  flag.
- **Solución:** `_interval_ms_to_seconds()` con suelo de 50 ms
  (`KEYLOG_MIN_INTERVAL_MS`), default 500 ms
  (`KEYLOG_DEFAULT_INTERVAL_MS`), `main()` convierte una vez,
  `keylog_read(interval=None)` usa el default documentado. Nota de
  interfaz: hasta v3.5 un usuario que pasara `--interval 0.5`
  "funcionaba" por accidente (0.5 s); ahora 0.5 ms se clampéa al suelo
  de 50 ms — es la corrección deliberada hacia la interfaz documentada,
  alineada con Go.
- **Archivos:** `client/vault_kernel_cli.py` (constantes, función,
  argparse, `main()`, `keylog_read`).
- **Cómo verificarlo:** (1) tests de unidades
  (`TestIntervalUnits`: 500→0.5 s, 200→0.2 s, suelo 10→0.05 s, default
  500); (2) arnés end-to-end del camino real de `main()`
  (`scripts/verify_r3_interval_fix.py`, fuera del repo):
  `--interval 500` → `time.sleep(0.5)`, `--interval 10` → `0.05` —
  sin el fix, el mismo arnés muestra `sleep(500.0)`; (3) paridad
  manual Go/Python con el mismo valor.

## Recomendaciones de seguridad generales para el resto de agentes

1. **Todo formato de reporte que cruza la frontera kernel→usuario
   necesita un fixture en tests.** `stats --json` se estrenó roto y
   `doctor` v3.4 llevaba el check de versión muerto porque nadie fijó
   el formato EXACTO del snprintf del módulo; ahora
   `report_test.go`/`test_cli_parsing.py` lo clavan — si tocas el
   formato en `src/ioctl.c`, la CI te lo recuerda.
2. **Paridad Go/Python: las unidades son parte de la interfaz.** Dos
   clientes hermanos con el mismo flag pero unidades distintas es una
   regresión silenciosa; los tests de unidades de `--interval` son el
   patrón a seguir para cualquier flag nuevo.
3. **En arneses con ioctls stubbed, el fake debe imitar el contrato de
   error real** (excepción/errno), no devolver "False": el `_ioctl` del
   cliente trata un retorno sin excepción como éxito y el bucle
   `--follow` no termina (descubierto aquí con un dump de traceback del
   propio arnés; el producto está bien).
