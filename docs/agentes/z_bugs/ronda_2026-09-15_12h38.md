## Corrección 1 (BAJA, paridad/UX sensible) — `give-root` Go ignoraba el error de `Atoi` del PID

- **Descripción:** el dispatcher Go hacía `pid, _ =
  strconv.Atoi(os.Args[2])`. Con un argumento NO numérico
  (`give-root abc`, `give-root 12x`, `give-root ""`), `Atoi` fallaba,
  el error se descartaba y `pid` quedaba en 0 → `giveRoot` interpreta
  0 como "self" → **el CLI se escalaba a sí mismo a root en lugar de
  dar error de uso**. El CLI Python (argparse `type=int`) rechaza el
  mismo input con `invalid int value`. Mismo comando, dos
  comportamientos según cliente — y el de Go ejecutaba una operación
  distinta a la pedida (una escalada) ante un simple typo.
- **Superficie afectada:** `client/go/cmd/vault_kernel/main.go`, case
  `give-root`. El modo texto y el ioctl no cambian: pid<=0 sigue
  siendo "caller" por contrato documentado del módulo
  (`src/ioctl.c`: `pid <= 0 → priv_esc treats it as "the caller"`).
- **Severidad:** BAJA (lab tool; la operación resultante era válida
  pero no la solicitada; sin impacto en el módulo ni en terceros).
- **Causa raíz:** el error de parsing descartado mezclaba "sin
  argumento" (= self, válido) con "argumento inválido" (que debe ser
  error de uso). La paridad Go/Python de esta ruta no estaba testeada
  (el parsing vivía inline en el `switch`, sin función que testear).
- **Solución:** parsing extraído a `parseGiveRootPID(args []string)
  (int, error)` — función pura testeable: sin argumento → 0 (self);
  argumento numérico pasa tal cual (incluidos negativos, que el
  módulo trata como caller); argumento NO numérico → `invalid PID:
  %s (numeric PID, or none for self)`; más de un argumento →
  `usage: vault_kernel give-root [pid]` (gramática estricta). El case
  `give-root` ahora propaga el error. Comentario en el código marca
  el fix de paridad v3.8.
- **Archivos:** `client/go/cmd/vault_kernel/main.go`
  (`parseGiveRootPID` + case), `client/go/cmd/vault_kernel/main_test.go`
  (`TestParseGiveRootPID`: nil→0; "1234"/"1"/"-5"/"0" pasan;
  "abc"/"12x"/"1.5"/""→error con pid=0; args extra→error).
- **Cómo verificarlo:** (1) `go test ./cmd/vault_kernel/ -run
  TestParseGiveRootPID -v` en verde; (2) los tests e2e Python de
  give-root de argparse no cambiaron (la referencia no se movió);
  (3) en la VM, `./vault_kernel give-root abc` con el módulo cargado
  debe imprimir `[-] Error: invalid PID: abc ...` y NO escalar.

## Corrección 2 (BAJA, robustez de gramática) — `keylog` Go aceptaba argumentos desconocidos en silencio

- **Descripción:** el case `keylog` solo reconocía el patrón `--follow
  [ms]` fijo: cualquier otro argumento en el camino one-shot se
  ignoraba (`keylog 500` sin `--follow` imprimía el buffer una vez,
  como `keylog` a secas), y el intervalo posicional solo se validaba
  tras un `--follow` exactamente en la posición 2. El CLI Python
  (argparse) rechaza argumentos desconocidos con error de uso.
- **Severidad:** BAJA (UX/robustez; el comportamiento silencioso
  podía hacer creer que el intervalo se aplicó).
- **Causa raíz:** parsing manual por posición (`os.Args[2]`,
  `os.Args[3]`) sin recorrido de argumentos; creció sin gramática.
- **Solución:** gramática extraída a `parseKeylogArgs(args []string)
  (keylogOpts, error)` — función pura: `--follow` y `--timestamps`
  aceptados en cualquier orden; intervalo posicional aceptado una vez
  y solo tras `--follow` (mínimo 50 ms, contrato v3.5 intacto, ahora
  con constantes `keylogDefaultIntervalMs`/`keylogMinIntervalMs`);
  cualquier otro token (flag desconocido, intervalo sin follow,
  segundo intervalo) es error de uso; `--timestamps` sin `--follow`
  es error en ambos clientes. El case `keylog` delega en el parser.
- **Archivos:** `client/go/cmd/vault_kernel/main.go` (`keylogOpts`,
  `parseKeylogArgs`, case, `printUsage` con `keylog [--follow [ms]]
  [--timestamps]`), `main_test.go` (`TestParseKeylogArgs`: 9 grupos
  de aserciones — defaults, posicional, orden de flags, errores).
- **Cómo verificarlo:** `go test ./cmd/vault_kernel/ -run
  TestParseKeylogArgs -v`; en la VM, `./vault_kernel keylog 500` debe
  dar error de uso (antes: ignoraba el 500); `./vault_kernel keylog
  --follow 200 --timestamps` debe seguir el stream con marcas.

## Recomendaciones de seguridad generales para el resto de agentes

1. **Los errores de parsing de argumentos nunca se descartan** — el
   patrón `x, _ := parse(x)` convierte un input inválido en un valor
   por defecto con SEMÁNTICA (aquí: self-root). Si el cero/nulo es un
   valor especial, el error de parsing es obligatorio.
2. **Paridad de gramática, no solo de salida:** los tests de paridad
   entre clientes hermanos deben cubrir los CAMINOS DE ERROR de los
   argumentos (ronda 4: rutas de fallo del JSON; ronda 5: argumentos
   inválidos). Patrón: para cada comando, un test de gramática con
   casos buenos y malos en al menos un cliente.
3. **`od -c` como única fuente de verdad para caracteres:** cualquier
   "corrección" de contenido sospechoso de truncado ANTES de una
   verificación con `od` arriesga corromper contenido válido (esta
   ronda lo estuvo a punto: los colores ANSI eran correctos).
4. **Verificar que el fix no rompe lo existente:** las suites completas
   (23 Go + 30 Python + 13 payloads + ruff CI + `make help`) se
   ejecutaron en verde tras los cambios, incluida la salida byte-
   idéntica de `keylog --follow` sin `--timestamps`.
