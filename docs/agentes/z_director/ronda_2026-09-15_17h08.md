## Hallazgo 1 (MEDIA, control plane) — la matriz de exit codes estaba partida

Reproducida en este entorno sobre el commit base (binario Go
compilado + script Python reales, sin módulo):

| Input | Go (pre-v3.12) | Python (pre-v3.12) |
|-------|----------------|--------------------|
| `version` | 0 | 0 |
| `hide-file` (falta operando) | **1** (¡error de dispositivo!) | 2 (argparse) |
| `hide-file a b` (sobra operando) | **1** (¡error de dispositivo!) | 2 |
| `hide-pid 0` (valor inválido) | **1** (¡error de dispositivo!) | 2 |
| `keylog --timestamps` (sin follow) | **1** (¡dispositivo!) | 2 (parser.error) |
| `keylog --stop-after 5` (sin follow) | **1** (dispositivo) | **1** (SystemExit) |
| `magic-encode pwn` (falta puerto) | **1** (uso, pre-device) | 2 (argparse) |
| `no-existe` | **1** | 2 |
| invocación desnuda | **0** | **1** |

- Tres clases de problema: (a) Go usa 1 para TODO; (b) Go parsea
  tras `openDevice()` — la decisión de la ronda 4 convierte cualquier
  error de gramática en error de dispositivo cuando el módulo no
  está; (c) Python mezcla parser.error (2) con SystemExit-string (1)
  para la MISMA clase de error, y la invocación desnuda diverge.
- **Clasificación:** los códigos de salida son CONTRATO en workflows
  scriptados (`$?` es la única forma de clasificar un fallo sin
  parsear texto). La matriz comando×cliente gana esta dimensión de
  forma permanente.

## Hallazgo 2 (MEDIA, leído de código) — un ioctl fallido en Python salía con exit 0

`VaultKernelClient._ioctl` captura `OSError`, imprime
`[-] ioctl failed: ...` y **devuelve False**; los comandos hacen
`if self._ioctl(...): print éxito` y terminan normalmente → exit 0.
Con el módulo cargado, un `hide-pid` rechazado por EPERM habría
salido con 0 — el cliente Go en la misma celda sale con 1. El
camino de error no-feliz era una mentira del shell. Reproducido por
lectura + test con mock de `fcntl.ioctl` tras el fix (exige exit 1).

## Hallazgo 3 (BAJA, superficie) — `help` no existe en Python

El mensaje de error de Go recomienda literalmente
"Run 'vault_kernel help' for usage"; en Python ese consejo moría con
"invalid choice" (exit 2). La superficie vuelve a 23 comandos en
ambos clientes (decisión en ADR 22).
