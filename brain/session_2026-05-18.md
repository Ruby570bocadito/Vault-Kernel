## Bugs Corregidos (7/7)

### B01 — Conflicto `vault_kernel_class` static vs extern
- **Archivos**: `core.h:96`, `ioctl.c:8`
- **Severidad**: Medium
- **Descripción**: core.h declaraba `extern struct class *vault_kernel_class;` pero ioctl.c la definía como `static`. Dos símbolos diferentes.
- **Fix**: Eliminado `extern` de core.h. Solo ioctl.c usa esta variable.

### B02 — Buffer overflow en LIST_HIDDEN ioctl
- **Archivo**: `ioctl.c:67-86`
- **Severidad**: High
- **Descripción**: `snprintf(p, 256, ...)` hardcodeaba buffer size. Con 128+ items ocultos → overflow.
- **Fix**: Reemplazado por `sizeof(kbuf) - (p - kbuf)` dinámico. Agregado guard clause `remaining > 32`.

### B03 — fdput() no llamada si f.file == NULL
- **Archivo**: `net_hide.c:138-144`
- **Severidad**: Medium
- **Descripción**: `fdput(f)` solo se llamaba dentro del bloque `if (f.file)`. Si `f.file == NULL`, el struct fd no se limpiaba (aunque `fdput(NULL)` es safe, no se llamaba).
- **Fix**: Movido `fdput(f)` fuera del `if` para que siempre se ejecute.

### B05 — strstr demasiado agresivo en ocultación de archivos
- **Archivo**: `file_hide.c:55`
- **Severidad**: Medium
- **Descripción**: `strstr(name, hidden_files[i])` hacía substring matching incondicional. Ocultar "a" ocultaba TODOS los archivos con "a".
- **Fix**: Substring matching solo si `hidden_files[i]` contiene '/' (indica path). Para nombres simples: `strcmp` exacto.

### B06 — Falta synchronize_rcu() en hooking cleanup
- **Archivo**: `hooking.c:15`
- **Severidad**: High
- **Descripción**: Al descargar el módulo, otra CPU podía estar dentro de un hook. Sin RCU sync → kernel panic.
- **Fix**: Agregado `synchronize_rcu()` después de restaurar todos los hooks originales.

### B07 — `class_create()` compatibilidad pre-6.4
- **Archivo**: `ioctl.c:162`
- **Severidad**: Medium
- **Descripción**: `class_create(DEVICE_NAME)` solo funciona en kernels >= 6.4. En kernels anteriores requiere `class_create(THIS_MODULE, DEVICE_NAME)`.
- **Fix**: `#if LINUX_VERSION_CODE >= KERNEL_VERSION(6,4,0)` para elegir la firma correcta.

### B08 (NUEVO) — ioctl command layout incorrecto en Python y Go
- **Archivos**: `client/vault_kernel_cli.py`, `client/go/internal/ioctl/ioctl_linux.go`
- **Severidad**: **CRITICAL**
- **Descripción**: Ambos clientes calculaban los ioctl commands con shifts incorrectos:
  - Antes: `dir<<30 | type<<22 | nr<<14 | size<<8`
  - Correcto (kernel): `dir<<30 | size<<16 | type<<8 | nr<<0`
  - Esto significa que **ningún ioctl funcionaba** — valores completamente diferentes a los que espera el kernel module.
- **Fix**: Corregida la fórmula en ambos clientes. Añadidos unit tests que validan contra valores pre-calculados.
- **Impacto**: Este bug hacía que el Python client nunca funcionara. Era imposible comunicarse con el módulo.

### B09 — Variable `vault_kernel_dev` extern sin uso
- **Archivo**: `core.h`
- **Descripción**: Declaración `extern dev_t vault_kernel_dev;` sin uso real (ioctl.c la define como `static`).
- **Fix**: Eliminada la declaración extern.
